## 9. Gotchas

- **Emulator job flake.** "Integration test (Android emulator)" often hangs
  35 minutes with no output, or the emulator dies at the end. Rerun failed
  jobs. A rerun uses the old merge snapshot, so after a fix lands on main run
  `gh pr update-branch N` first. Other emulator infra errors (corrupt system
  image download) also appear in "Release APK launch". If a job fails fast
  with real output, read the log; do not just rerun.
- **Worktrees:** create them with `git worktree add ../NAME -b BRANCH origin/main`
  (the path is relative to the current directory; `-C` puts it inside the repo).
  Short names (Windows long paths). Delete a worktree with
  `git worktree remove --force`; for long paths use `cmd /c rd /s /q "\\?\C:\..."`.
  `FE-fix1` may be in use by another session on `feat/v2-chrome`; do not touch it.
- `flutter pub get` dirties `windows/` plugin files: run `git checkout -- windows`
  and never commit them. Flutter is at `C:\src\flutter\bin`, not on the bash PATH;
  use PowerShell for flutter and dart.
- Python that edits ARB files must read and write UTF-8 explicitly (German umlauts).
- Local release APKs need `flutter pub get --enforce-lockfile` and
  `flutter build apk --config-only`, or the app shows the boot-failure screen
  (no GeneratedPluginRegistrant). CI's artifact is the safe test.
- C: drive is tight (6.9 GB free at handoff, shared with other writers).
  Emulator snapshots under `C:\Users\Mahdi\.android\avd\fe_api34.avd\snapshots`
  are safe to delete. No Gradle/APK builds locally unless needed.
- The owner's main checkout `C:\Users\Mahdi\Downloads\FighterEdge` is on the
  stale branch `feat/ai-eval-and-camp-domain` with uncommitted edits. Do not
  edit or build from it; deploy from a clean worktree of main.
- Playwright `fill` does not drive Flutter text fields; click then type slowly.
- Flaky-by-seed tests: the reaction conformance test was failing about 1 in 3
  runs until #61. If a seeded/random test fails, check for unseeded `Random()`.
