## Keep these distinctive choices

Oswald headings and Barlow reading text make a coherent athletic voice. Large timer and reaction numerals have a task, not decorative status. Crimson marks a real next action; the deeper primaryFill is more legible than bright crimson with white text. Gold marks Pro access, including clearly labeled teasers. Nutrition colors carry labels and quantities; warnings include words/icons as well as color. Real recipe credits remain visible. Drill studied/drilled/sharp progress helps recall. Sheets focus destructive or input tasks, and deletion requires typed confirmation. Existing motion helpers and component variants keep the system restrained.

The slop verdict is mixed mainly for oversized empty-state type and an equally heavy Home card stack. It is not a verdict against dark mode, condensed type, useful cards, chart rings or real credited recipe photos. The login photo supplies atmosphere, though provenance needs an owner answer. The TODAY red bar has a useful scheduled-session role and a weaker empty-state role. Solid crimson primary actions are functional; gradients that darken the login photo preserve text legibility rather than add decoration.

## Implemented design and verification

DESIGN.md was written before edits. No new token/component needed a gallery entry. The accessibility slice changes semantic boundaries, so its before/after images intentionally look the same; semantic activation tests prove the behavioral difference. The contrast slice changes two role usages, not color values. The auth slice adds three EN/DE messages and wraps only Login errors; it preserves autofill, paste, visibility and server failures. A six-character existing account can still sign in.

An early auth full run failed eight text expectations after my initial Windows file edit corrupted UTF-8 punctuation. I restored both ARBs from origin/main, inserted only three keys, regenerated, and reran the checks. The final diff contains no unrelated localization changes. The first large-text auth regression test also found clipped single-line errors; an opt-in wrapping property fixed that before final capture. These failed checks informed corrections and are not represented as passes.

No golden was regenerated. Shared visual structure stays the same, and the existing three goldens are checked unchanged. Before/after files are in FighterEdge-screens/before-after/<slice>/{before,after}. Their fixture method differs from the original Chrome images; comparisons use matched fixture/font/size/state, never a browser-to-fixture pixel claim. Secondary routes and conditionally reached sheets share the tested control implementation; the capture index identifies which host/state was actually shown.

New worktree dependency resolution stopped at Windows' existing symlink/Developer Mode prerequisite after creating package configuration. No system setting was changed. Supported --no-pub test/analyze/build commands used the resolved dependency graph. This is not an Android/iOS build or store-readiness check. The offline JS build succeeded; its unsupported flutter_tts Wasm and missing Cupertino font warnings do not prove native behavior.
