## Unavailable or partial states

- Native Google/Apple account sheets, real email delivery, platform password managers: offline local sign-in cannot represent them. Wrong local code was captured; production auth was inspected only in code.
- Real RevenueCat checkout, restore, sandbox receipts, Firebase/webhook responses: fake billing captures layout/results only. No purchase or entitlement readiness claim.
- Native status bar/safe areas/keyboard/haptics/voice/motion/launch/icon: no connected device or installed AVD. Native feel and motion were NOT reviewed.
- Light theme: intentionally absent. Tablet, landscape and every conditional error/empty state were not exhaustively captured.
- TalkBack/VoiceOver and switch-control reading/activation: no phone; Chrome semantics plus widget activation tests cover only specified boundaries.
- 200%/high-contrast/320 tests cover ten key screens and recaptured changed hosts, not every long scrolled state. CSS text-spacing overrides do not test Flutter glyph layout.
- Secondary conditional verification, consent/ad/privacy sheets and every recipe/detail state share changed buttons but do not all have matched before/after captures. The general component behavior is tested; those exact screen states remain unverified.

Cross references: 02 first Home/tour belongs to onboarding; 03 holds Home day/fight states; 07 original Home countdown frames stay in fight-camp; 09 holds Pro Home/Profile/Coach and loaded recipes; 10 holds loading and confirmation states; 11/12 are language/accessibility variants of those base screens.
